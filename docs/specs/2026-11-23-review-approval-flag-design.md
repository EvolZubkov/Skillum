# Флаг «Согласовано» в режиме рецензирования: дизайн

Дата: 2026-11-23. Статус: черновик на согласование. Расширяет PRD-52.

## Цель

Рецензент может поставить на объекте теста отметку «Согласовано», не прибегая к
комментарию. Отметка у каждого рецензента своя. Автор видит, кто и когда согласовал,
в окне рецензирования, в навигаторе по вопросам и в редакторе теста.

## Решения

1. Отметка принадлежит паре «рецензент, объект», а не ветке комментария. Хранится в
   отдельной таблице `test_review_approvals`.
2. Согласовать можно любой объект, на который можно оставить комментарий: вопрос,
   страницу содержимого, тему (раздел), экран старта, экран результатов и тест в
   целом. Словарь якорей и резолвер якоря общие с комментариями
   (`shared/review/anchor`), второй копии нет.
3. Один рецензент и один объект дают не более одной отметки. Снять отметку может
   только её автор; снятие удаляет строку.
4. Отметка пинуется к содержимому (`pinned_content_hash`). Если объект изменён после
   отметки, она остаётся видимой с признаком «по прежней редакции» и не считается
   действующим согласованием.
5. Отметка на тесте в целом не каскадирует на вопросы и обратно. Каждый уровень
   самостоятелен.
6. Рецензент НЕ видит согласований других рецензентов (решение владельца 2026-11-23):
   ни имён, ни дат, ни счётчиков «N из M», ни круга на бейджах. Он видит только свои
   отметки. Это отличается от комментариев, которые рецензенты по решению PRD-52 видят
   друг у друга: комментарий - обсуждение, согласование - независимая оценка. Все
   отметки видят только автор и владелец теста (доступ на правку). Фильтр по зрителю
   выполняется на сервере: рецензенту отдаются только его строки.
7. Читать отметки может тот, кто проходит гейт `requireReviewScope` (грант `review` или
   доступ на правку). Ставить и снимать отметку может только держатель гранта `review`
   на этом тесте. У автора и владельца теста собственной отметки нет (решение
   владельца 2026-11-23): они согласование принимают, а не дают. Роль не проверяется.
8. Бейдж в навигаторе рисует хост отладочного плеера, а не шаблон. Контракт шаблона
   не меняется, боевые пакеты остаются прежними. Хост ставит на точку атрибут
   `data-review-approved` (`all` / `part` / `stale`), а бейдж рисует CSS-псевдоэлемент
   `::before` (стиль в `tb-components.css`): узлов в DOM экрана нет, поэтому перерисовка
   экрана на каждом вопросе бейдж не стирает, хосту достаточно повторить разметку
   атрибутов после каждой отрисовки. Верхний угол точки занят `is-flagged::after`,
   бейдж стоит в нижнем правом. Знак галочки - символ `✓` в тексте псевдоэлемента:
   иконки lucide в CSS внутри iframe пакета недоступны.

9. Знаменатель счётчика «согласовали N из M» (решение владельца 2026-11-23) - только
   рецензенты, принявшие приглашение. Состояния «принял» в модели сейчас нет (грант
   выдаётся при приглашении), поэтому вводится поле `test_access_grants.accepted_at`
   (nullable): ставится при первом обращении держателя гранта `review` к окну
   рецензирования этого теста (первое чтение ленты или отметок). Вход в систему по
   `users.last_login_at` не годится: он не привязан к тесту. У грантов, выданных
   до выпуска, поле остаётся пустым, пока рецензент не откроет окно снова; такие
   рецензенты в знаменатель не входят. Рецензент, поставивший отметку, считается
   принявшим всегда.

10. Вкладка «Комментарии» переименована в «Рецензирование» (решение владельца 2026-11-23):
    её роль шире ленты комментариев. Относится к ящику редактора теста, к инспектору
    окна рецензирования и к отладчику PRD-18. Внутри два раздела: «Согласование»
    (таблицы рецензентов и объектов) и «Комментарии» (лента). Счётчик на вкладке остаётся
    числом открытых комментариев. Ссылка `?review=<id>` не меняется. Приглашённые
    рецензенты остаются отдельной вкладкой, объединение отложено. Название менялось в
    эскизах, спеке PRD-52, руководстве автора и контракте редактора; код, тесты и
    исторические планы переименовываются вместе с реализацией трека.

11. Точка карты знает только индекс `goto:N` внутри текущей выдачи, а отметка хранится
    по `question_id`. Хосту нужно соответствие «индекс - вопрос» для текущего варианта.
    При случайной выборке и в адаптиве оно зависит от прогона; источник - вкладка
    «Выдача» инспектора (`TBInspector`) и список выданных вопросов прогона. Без него
    бейдж на точке поставить нельзя; это проверяется первым при реализации.

## Данные

Дополнительно к таблице ниже: колонка `test_access_grants.accepted_at` (timestamp,
NULL). Менять только строки с `access_level = 'review'`.

Таблица `test_review_approvals` (миграция следующего номера в серии drizzle):

| Поле | Тип | Смысл |
| --- | --- | --- |
| `id` | varchar(36), PK | идентификатор |
| `test_id` | varchar(36), cascade | тест |
| `reviewer_id` | varchar(36) | кто согласовал |
| `anchor_kind` | text, тот же enum, что у комментариев | вид якоря |
| `question_id`, `topic_id`, `content_page_id` | как у комментариев | якорь |
| `context_label` | text | снимок контекста строкой |
| `pinned_content_hash` | text, NULL для экранов и теста | хеш содержимого на момент отметки |
| `approved_at` | timestamp, not null | дата и время проставления |

Индексы: `(test_id)` для чтения ленты и уникальный индекс на
`(test_id, reviewer_id, anchor_kind, coalesce(question_id, topic_id, content_page_id))`.
Выражение в индексе живёт только в SQL миграции, не в модели drizzle (как у
`users.external_key`), поэтому `db:push` его не знает; это фиксируется в CLAUDE.md.

## API

Файл `server/routes/review.ts`, под тем же `reviewGate`.

- `GET /api/tests/:id/review/approvals` - отметки теста с пометками `stale` и
  `orphaned` (тот же сервис `review-anchor`) и именем рецензента. Держателю гранта
  `review` без доступа на правку возвращаются только его собственные строки; автору и
  владельцу - все.
- `PUT /api/tests/:id/review/approvals` - поставить отметку своим именем по якорю;
  только для держателя гранта `review` (иначе 403, даже у владельца теста). Повторный
  вызов идемпотентен: время не обновляется.
- `DELETE /api/tests/:id/review/approvals/:approvalId` - снять свою отметку; чужую
  снять нельзя, в том числе владельцу теста (по аналогии с комментариями).

Данные теста уходят и в перенос теста: таблица добавляется в
`test-transfer-completeness`.

## Интерфейс

Эскиз обязателен до разработки интерфейса (правило wireframes-first); пункты ниже
описывают намерение, а не утверждённую раскладку.

1. Вкладка «Рецензирование» (`ReviewPanel`): раздел «Согласование» над лентой
   комментариев. В нём две карточки: «Тест в целом» и текущий объект (вопрос) с
   чекбоксом «Согласовано», датой и временем отметки и признаком «по прежней редакции».
   Согласование теста целиком - на этой же вкладке, а не в статусной панели окна. У
   рецензента в карточках только его отметка; у автора чекбокса нет, он видит всех
   согласовавших с датой и временем и счётчик «N из M».
2. Навигатор по вопросам в отладочном плеере: на точке вопроса бейдж-галочка. Бейдж
   ставит хост через атрибут `data-review-approved` на `.ou-quiz__dot`; данные
   передаются из страницы отладочного плеера в iframe через shim. Бейдж один на
   точку, и его смысл зависит от зрителя. У рецензента он описывает только его
   собственную отметку: сплошной - согласовал, пунктирный - объект правили после его
   отметки. У автора и владельца - круг рецензентов: сплошной (согласовали все),
   контурный (часть), пунктирный (правили после отметки); кто и когда согласовал, видно
   в подсказке точки и в блоке «Согласование» вкладки.
   Атрибут ставится на точки обоих мест карты: строки (`[data-qnav-dots]`) и панели
   «Все вопросы» (`[data-qnav-panel]`, точки размера `l`) - у них один селектор
   `.ou-quiz__dot[data-action^="goto:"]`. При листании строка прячет точки не с
   текущей страницы, так что у длинного теста панель - основное место, где видны все
   маркеры. В легенду панели хост добавляет строки (`ou-quiz__legend-dot` с тем же атрибутом): у
   рецензента две («вы согласовали», «правили после вашей отметки»), у автора три;
   шаблон и контракт не меняются. Те же строки показаны внизу вкладки «Рецензирование»
   окна рецензирования под заголовком «Обозначения на карте вопросов»: в строке карты
   при листании легенды нет. На телефоне карты нет, маркеров там тоже.
3. Редактор теста, вкладка «Рецензирование». Вкладка устроена рейлом, как остальные
   вкладки ящика: слева рейл из двух пунктов, «Согласование» и «Комментарии» (на
   пункте число открытых комментариев), справа содержимое выбранного пункта с
   заголовком раздела над ним (`ou-formsection--stacked`); прокручивается только
   содержимое, рейл остаётся на месте. Раздел «Согласование»: сверху таблица
   рецензентов (отметка на тест целиком, число согласованных вопросов, дата и время).
   Ниже согласование по объектам, рассчитанное на большой тест:
   - сводка по разделам: аккордеон `ou-acc ou-acc--plain`, заголовок раздела: название
     одной строкой, под ним подпись «согласовано всеми N из M · до правки N · не
     согласовано N» (нулевые числа не пишутся), справа узкая полоса прогресса. Раскрыты только разделы, где есть
     что разбирать; раздел без замечаний при фильтре «Требуют внимания» скрыт, а строка
     под списком говорит, сколько разделов скрыто. Высота сводки растёт на одну
     строку на раздел, а не на несколько;
   - фильтр `ou-seg` «Требуют внимания» (по умолчанию) / «Все» / «Не согласованы» /
     «До правки», поиск по тексту вопроса и выбор рецензента;
   - внутри раздела матрица: строка - вопрос, столбец - принявший рецензент (аватар и
     фамилия в шапке), в ячейке дата и время отметки, жёлтый контурный тег у устаревшей отметки,
     «—» у пустой ячейки (значения поясняет легенда под таблицей). Строка фиксированной высоты, без переносов, сколько бы
     рецензентов ни было; при числе рецензентов больше шести матрица прокручивается по
     горизонтали с закреплённым столбцом вопроса;
   - постраничность внутри раздела (по 20 строк), переключатель внизу матрицы.
   Рецензент, не принявший приглашение, в матрицу не входит (решение 9). Привязка
   строки рецензента к фильтру (клик по строке верхней таблицы) отложена.
   Тот же набор отметок в рейле «Вопросы теста» (по аватарам рецензентов) в этот
   эскиз не входит.
   Форма вкладки не выходит за границы окна ни при каком числе разделов, вопросов и
   рецензентов: колонки сжимаются, длинный текст вопроса режется многоточием (полный
   текст в подсказке), матрица при необходимости прокручивается внутри раздела.

## Тесты

- Интеграционные на pglite: уникальность, идемпотентность, снятие чужой отметки (403),
  каскад при удалении теста, `stale` после правки вопроса, рецензент не получает чужих отметок (`GET` возвращает только его строки, автору - все).
- Клиентские: переключатель панели, бейдж на точке, строки редактора.
- Полный прогон не запускается; только целевые файлы.

## Документация после выпуска

Спека PRD-52, руководство автора, контракт шаблона не затрагивается, новая строка в
`docs/reports/ANALYSIS_*.md` (рецензирование: согласование по рецензентам).
