## 1. Обзор

### 1.1 Контекст

При включённом «Разрешить возврат к неотвеченным вопросам» (PRD-19 FR-01) участник свободно
пропускает вопросы и возвращается к ним, а раздел или тест завершает с экрана обзора кнопкой
«Завершить раздел» или «Завершить тест». Если вопросы без ответа остались, появляется окно
подтверждения (PRD-19 FR-09), и после него неотвеченные засчитываются как неверные (FR-07).

Для части тестов это неприемлемо. Опросник или измерительный тест со шкалами теряет смысл, если
профиль построен по половине ответов. Оцениваемый тест, где методика требует ответа на каждое
задание, тоже не должен закрываться с пропусками по одному клику. Сегодня автор может запретить
пропуск только целиком, выключив возврат, но тогда участник теряет и свободу порядка ответов.

### 1.2 Цель

Дать автору настройку теста, при которой раздел или тест нельзя завершить, пока в нём остаётся
вопрос без ответа. Свобода навигации внутри раздела сохраняется: участник по-прежнему пропускает
вопросы, возвращается к ним и отвечает в любом порядке в пределах отведённого времени. Кнопка
завершения на обзоре неактивна, а подсказка объясняет почему.

### 1.3 Метрики успеха

| Цель | Метрика |
| --- | --- |
| Запрет действует | При включённой настройке ни один раздел и ни один тест не завершается участником с вопросом без ответа, кроме принудительных завершений §3.4 |
| Причина понятна | На обзоре с неактивной кнопкой всегда есть подсказка с числом оставшихся вопросов |
| Хосты одинаковы | Веб и SCORM-пакет показывают одну кнопку, одну подсказку и одно число (паритет PRD-12) |
| Ничего не сломано | Тесты без настройки ведут себя как до выпуска |

## 2. Пользователи

### 2.1 Автор теста

Включает настройку в «Правила прохождения» → «Навигация».

### 2.2 Участник

Проходит тест с включённой настройкой: видит неактивную кнопку завершения и подсказку, отвечает на
оставшиеся вопросы, после чего кнопка становится активной.

## 3. Ключевые понятия

### 3.1 Охват

Охват — множество вопросов, которое закрывает кнопка завершения. Он совпадает с охватом обзора
PRD-19:

- тест по темам (`linear_by_topics`, `router_by_topics`) — текущий раздел;
- сплошной тест (`linear_flat`) — весь тест.

В охват входят ВСЕ вопросы раздела или теста, включая ещё не выданные участнику. Иначе обзор,
открытый кнопкой «К обзору» в середине раздела, позволил бы закрыть раздел, просто не дойдя до его
конца.

### 3.2 Вопрос без ответа

Вопрос считается отвеченным, только если ответ ОТПРАВЛЕН (статус `answered`, PRD-19 FR-03a).
Черновик (FR-03b) и пропуск (`skipped`) ответом не считаются. Корректность ответа значения не имеет.

### 3.3 Действующее значение настройки

Настройка действует, только когда включён возврат к неотвеченным. Без возврата прохождение строго
линейное, «Пропустить» нет, и к обзору участник приходит со всеми ответами. Поэтому правило
проверяет оба признака, а не полагается на то, что редактор сбросил значение: книга Excel или
перенос `.tbtest` могут принести сочетание «настройка ВКЛ, возврат ВЫКЛ».

### 3.4 Принудительное завершение

Запрет касается только завершения, которое участник выбирает сам кнопкой обзора. Не ограничиваются:

- истечение времени теста или раздела (PRD-19 FR-15, PRD-20);
- закрытие раздела при выходе и завершение теста без разделов при выходе (PRD-67);
- запасной путь рантайма, когда у шаблона нет макета `review` (раздел или тест завершается сразу).

Во всех этих случаях неотвеченные засчитываются как неверные, как и сегодня.

### 3.5 Скрытый экран обзора

Автор может скрыть системный экран обзора целиком (вкладка «Структура», признак `hidden` у строки `review`,
общее правило `isSystemScreenHidden`). Сегодня тогда раздел с пропущенными вопросами завершается сразу после
последнего вопроса, минуя обзор, и запрет PRD-73 не сработал бы.

Поэтому при действующей настройке и хотя бы одном вопросе без ответа в охвате обзор показывается, даже если
автор его скрыл; кнопка завершения на нём неактивна (FR-04). Когда отвечено всё, скрытый обзор не показывается,
как и задумал автор. Так же устроено «Не показывать обзор, если отвечены все вопросы»: путь к пропущенным
вопросам не отнимается. Решение владельца 2026-11-24.

## 4. Функциональные требования

| ID | Требование |
| --- | --- |
| FR-01 | Настройка теста `requireAllAnsweredToFinish` («Требовать ответ на все вопросы перед завершением»), по умолчанию выключена |
| FR-02 | Настройка зависит от `allowReturnToUnanswered`: при выключенном возврате переключатель недоступен с причиной, выключение возврата сбрасывает значение; рантайм проверяет оба признака (§3.3) |
| FR-03 | Завершение запрещено, если настройка действует и в охвате (§3.1) есть хотя бы один вопрос без ответа (§3.2), включая невыданные |
| FR-04 | Пока завершение запрещено, каждая кнопка `[data-action="finish-review"]` на обзоре неактивна (`disabled`), а клик по ней хост не исполняет; вариант кнопки (primary или ghost) задаёт макет, как и сегодня |
| FR-05 | Пока завершение запрещено, подсказка обзора (`review.hint`) — «Чтобы завершить раздел, ответьте на все вопросы. Осталось без ответа: N.»; в форме «завершить тест», когда подпись кнопки «Завершить тест». N — число вопросов без ответа в охвате, включая невыданные. Текст фиксированный, автор его не настраивает |
| FR-06 | Принудительные завершения §3.4 запретом не ограничиваются |
| FR-07 | При действующей настройке окно подтверждения PRD-19 FR-09 не появляется: к моменту, когда кнопка активна, вопросов без ответа нет |
| FR-08 | Когда отвечено всё, обзор ведёт себя как сегодня, включая «Не показывать обзор, если отвечены все вопросы» |
| FR-09 | Адаптивные темы и адаптивный режим настройку игнорируют: пропуска там нет, порядок ведёт лестница уровней |
| FR-10 | Поле проходит все каналы теста: редактор, API, снимок публикации, SCORM `TEST_DATA`, ответы старта и возобновления веб-попытки, книга Excel и перенос `.tbtest` |
| FR-11 | Выключенная настройка не меняет поведения ни одного хоста |
| FR-12 | Скрытый автором экран обзора показывается, пока настройка действует и в охвате есть вопрос без ответа (§3.5) |

### 4.1 Почему без проверки на сервере

Веб-сервер не проверяет запрет при `finish`. Обойти его, вызвав API мимо интерфейса, участнику
невыгодно: неотвеченный вопрос засчитывается как неверный (FR-07 PRD-19), поэтому обход только
снижает его результат. В SCORM-пакете проверять негде, всё решает клиент. Серверная проверка
вдобавок обязана была бы отличать добровольное завершение от принудительного (§3.4), а сервер сегодня
этого различия не хранит.

## 6. Общее правило и обзор

### 6.1 Правило (`shared/flow/finish-gate.ts`)

Новый чистый модуль рядом с `review-gate.ts`, его импортируют оба хоста (пакет — через бандл
`TBTemplate`):

```ts
export interface FinishGateInput {
  requireAllAnsweredToFinish?: boolean;
  allowReturnToUnanswered?: boolean;
  /** Whether the scope holds a question without a submitted answer, undelivered included. */
  hasUnanswered: boolean;
}

/** True when the learner may not finish the scope from the review screen. */
export function isFinishBlocked(input: FinishGateInput): boolean;

/** True when the author's «hide the review screen» applies right now (§3.5). */
export function reviewHiddenByAuthor(hidden: boolean, input: FinishGateInput): boolean;
```

Правило запрета: `requireAllAnsweredToFinish && (allowReturnToUnanswered ?? true) && hasUnanswered`.
Скрытие автором действует, когда `hidden && !isFinishBlocked(input)`.

### 6.2 Построитель обзора (`shared/template/review-context.ts`)

`buildReviewContext` получает вход `requireAllAnsweredToFinish` и `allowReturnToUnanswered`. Список
вопросов у него уже полный: невыданные приходят с `delivered: false`. Построитель:

1. считает число вопросов без ответа по ВСЕМ вопросам охвата, не фильтруя `delivered`;
2. вызывает `isFinishBlocked` с `hasUnanswered` = «это число больше нуля»;
3. возвращает в `review` новый признак `finishBlocked` и, при истине, текст подсказки FR-05 вместо
   прежнего; глагол подсказки следует подписи кнопки (`finishLabel`).

Список «Без ответа» по-прежнему содержит только выданные вопросы: формулировки невыданных участник ещё
не видел. Поэтому в обзоре, открытом кнопкой «К обзору», число в подсказке может быть больше числа в
списке (состояние `s-midflow` эскиза).

### 6.3 Почему все пути к завершению проходят через обзор

Автоматическое завершение раздела или теста без обзора (последний вопрос раздела, «Далее» на
последнем вопросе теста, выход из темы на хаб маршрутизатора) происходит только тогда, когда хост
решил обзор не показывать. Решение складывается из двух проверок: экран не скрыт автором
(`isSystemScreenHidden`) и `shouldShowReview` вернул истину. При включённом возврате и хотя бы одном
вопросе без ответа `shouldShowReview` возвращает истину, а скрытие автором при действующей настройке
снимается (§3.5, FR-12). Значит, путь с пропуском всегда ведёт на обзор.

Для этого в `finish-gate.ts` есть вторая функция — `reviewHiddenByAuthor(hidden, input)`: истина,
только когда экран скрыт И завершение не запрещено. Оба хоста подставляют её вместо прямого чтения
признака `hidden` в своих воротах обзора (`wantsReview` веба, `reviewIsWorthShowing` пакета). Тест
обязан это закрепить (§10).

## 7. Поведение хостов

### 7.1 Общий приём

Макет `review` не обязан знать о запрете: после отрисовки обзора хост ставит `disabled` на каждый
элемент `[data-action="finish-review"]` и не исполняет клик по нему. Так запрет работает в любом
шаблоне, включая внешние, без правки их макетов. Подсказка приходит через уже существующее поле
`review.hint`, которое выводит любой шаблон обзора. Сама простановка — общая функция в
`shared/template/` (экспорт `TBTemplate`), чтобы хосты не расходились.

### 7.2 SCORM-пакет

`renderReviewScreen` в `mainRender.js` передаёт в `buildReviewContext` настройки из `TEST_DATA`,
после `renderScreenInto` вызывает общую простановку, а обработчик `finish-review` первым делом
проверяет `built.review.finishBlocked` и при истине ничего не делает.

### 7.3 Веб-хост

`take-test.tsx` передаёт настройки из `navSettings` в `buildReviewContext`. Простановка выполняется
после монтирования макета в Shadow DOM `TemplateScreen`, а `doFinish` возвращается сразу при
`finishBlocked`.

## 8. UI

### 8.1 Автор

«Правила прохождения» → «Навигация», переключатель сразу под «Разрешить возврат к неотвеченным
вопросам» (эскиз, состояния `s-on` и `s-no-return`):

- подпись: «Требовать ответ на все вопросы перед завершением»;
- описание: «Кнопка «Завершить раздел» или «Завершить тест» станет активной, когда ответ дан на
  каждый вопрос. Когда истекает время, раздел или тест завершается как обычно.»;
- при выключенном возврате переключатель недоступен, под ним `Banner` (`warning`, `sm`, без иконки)
  «Доступно только при включённом возврате к неотвеченным.»;
- выключение возврата сбрасывает значение, как у свободной навигации.

### 8.2 Участник

Обзор по эскизу (состояния `s-blocked`, `s-midflow`, `s-complete`): кнопка завершения неактивна,
подсказка FR-05 стоит на месте `review.hint`. Карта вопросов, список «Без ответа», таймеры и
переходы не меняются.

### 8.3 Контекст шаблона и поставляемый шаблон

В контекст обзора добавляется `review.finishBlocked: boolean` — для шаблонов, которым нужно своё
оформление запрета. Это минорный подъём контракта: спека платформы (раздел о `review.*` и «История
версий»), руководство разработчика шаблонов (номер версии в трёх местах), PDF через `npm run docs:pdf`.
Номер версии берётся на момент влития: параллельный трек уже держит 3.22.0, столкновения номеров
проверяются перед подъёмом. Поднят до 3.23.0 (спецификация платформы, §10.15).

Макет `review` шаблона «Стандартный» (`server/scorm/templates/default/layouts/review.html`)
связывает подсказку с кнопкой: строка `tb-scene__qhint` получает `id="review-hint"`, а обе кнопки
`finish-review` — `aria-describedby="review-hint"`; признак `disabled` макет выводит сам по
`review.finishBlocked`, простановка хоста его дублирует. Версия манифеста поднимается (минорно).

Макет `review` у вынесенных шаблонов «Сертификация» и «Стандартный Ростелеком» обязан совпадать с
«Стандартным» знак в знак (тесты паритета `template-layout-parity` и `template-parity-standard-rt`),
поэтому та же правка перенесена в их репозитории решением владельца 2026-11-24: «Сертификация» 1.35.0,
«Стандартный Ростелеком» 1.23.0, у каждого пересобран `preview.html` и поставлен тег. Без этой правки
запрет и подсказка в них тоже работали бы — кнопку отключает хост, — но паритет макетов разошёлся бы.
Поставляемый «Стандартный» — 1.29.0.

## 9. Совместимость

- Умолчание `false`: существующие тесты не меняют поведения.
- Пакеты, выгруженные до выпуска, поля не содержат и работают как раньше; настройка действует после
  переэкспорта.
- Книга Excel без нового параметра импортируется с `false`.
- Старые шаблоны без `review.finishBlocked` получают запрет через простановку хоста (§7.1).

## 10. Критерии приёмки

- [ ] Модуль `finish-gate`: настройка ВЫКЛ, возврат ВЫКЛ, ноль без ответа, невыданные в охвате — тестами.
- [ ] `buildReviewContext`: `finishBlocked`, текст подсказки в формах «раздел» и «тест», число с
      невыданными при `delivered: false` — тестами.
- [ ] Автоматические пути завершения (§6.3) при включённом возврате и пропуске ведут на обзор — тестами
      обоих хостов.
- [ ] Редактор сверен с эскизом в браузере: место, подпись и описание дословно, баннер при выключенном
      возврате, сброс значения.
- [ ] Веб в браузере: конец раздела с пропусками — кнопка неактивна, подсказка с числом; ответ на
      последний пропущенный — кнопка активна, окна подтверждения нет; «К обзору» в середине раздела —
      кнопка неактивна, число учитывает невыданные.
- [ ] Веб: истечение времени раздела и закрытие при выходе (PRD-67) завершают раздел с пропусками.
- [ ] SCORM в локальном плеере (`npm run scorm:player`): те же сценарии, сверка с эскизом.
- [ ] Скрытый автором обзор: при пропусках показывается с неактивной кнопкой, при полностью отвеченном
      разделе не показывается — тестами обоих хостов и в браузере на вебе.
- [ ] Маршрутизатор: тема с пропусками не закрывается кнопкой обзора; хаб не меняется.
- [ ] Сплошной тест: «Завершить тест» неактивна, подсказка «Чтобы завершить тест, …».

## 12. Решённые вопросы

| Вопрос | Решение (2026-11-24) |
| --- | --- |
| Уровень настройки | Тест; действует на каждый раздел и на сплошной тест |
| Как показывать запрет | Неактивная кнопка завершения на обзоре; кнопки отключает хост, а не макет (подход А) |
| Подсказка | Всегда, текст фиксированный, отдельной настройки нет |
| Где подсказка | На месте `review.hint` под заголовком обзора: это поле уже выводит любой шаблон |
| Учитывать ли невыданные вопросы | Да: охват — весь раздел или тест; число в подсказке учитывает и их |
| Время и выход | Истечение времени и PRD-67 завершают раздел или тест несмотря на запрет |
| Проверка на сервере | Не нужна (§4.1) |
| Скрытый автором обзор | Показывается, пока есть вопросы без ответа; при полностью отвеченном охвате скрыт, как задумал автор (§3.5) |
