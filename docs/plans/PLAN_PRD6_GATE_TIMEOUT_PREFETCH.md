# План: гейт PRD-6 — таймаут, ранний запрос, индикатор ожидания, время из заголовка

Дата: 2026-11-18. Статус: согласован и реализован 2026-11-18, приёмка на стенде WebTutor впереди.

## Проблема

У учащегося с длинной историей обучений плагин `webtutor_cooldown` не укладывается в
бюджет гейта и падает по таймауту. Причины:

- бюджет `GATE_TIMEOUT_MS = 5000` зашит в `gate.js` (NFR-06);
- шаги идут последовательно: ожидание `window.load` (вендорные `html2canvas`, `jspdf`),
  `SCORM.init`, чтение `suspend_data`, GET `/` за доверенной датой с отдельным лимитом
  2500 мс, и только после этого POST коллекции обучений;
- POST получает остаток бюджета, а не весь бюджет;
- всё это время учащийся видит статичную строку «Загрузка теста...».

## Решения владельца

- Таймаут по умолчанию 30 с, переопределяется полем `timeoutMs` в конфиге плагина.
- Индикатор ожидания: вариант А, спиннер. Эскиз согласован:
  `docs/wireframes/approved/prd6-gate-waiting.html`.
- Запрос списка обучений стартует раньше всех прочих процедур пакета.
- Доверенная дата берётся из заголовка `Date` ответа запроса списка обучений.

## Шаги

### Ш1. Таймаут из конфига плагина

- `shared/eligibility/registry.ts`: в конфиг `webtutor_cooldown` добавить
  `timeoutMs: 30000` с комментарием.
- `gate.js`: `DEFAULT_TIMEOUT_MS = 30000`; функция `gateTimeoutMs(td)` берёт
  `retakePlugin.config.timeoutMs`, если это конечное положительное число, иначе значение
  по умолчанию. `GATE_TIMEOUT_MS` удаляется.
- Таймеры отрисовки после вердикта (4000 и 4500 мс) не меняются.

### Ш2. Ранний запуск запроса

- В конце модуля `RetakeGate` (`gate.js` склеивается после `testData.js`, так что
  `TEST_DATA` уже определён): если `isGated(TEST_DATA)`, вызвать `prefetch(TEST_DATA)`.
- `prefetch` сбрасывает `TrustedNow.reset()`, запоминает монотонный момент старта
  (от него отсчитывается бюджет) и запускает цепочку GET `/` (SECID, person id) и
  POST коллекции. Результат: `{ records, json, dateHeader }`. Обещание сохраняется в
  модуле.
- Параметры POST не зависят от даты: `_dc` берётся из `Date.now()`, а не из
  `todayDate`; название курса доступно из `TEST_DATA` (`lmsCourseName`).
- `run()` больше не вызывает `TrustedNow.reset()` (он сбросил бы начатый запрос) и
  берёт сохранённое обещание; если ранний запуск не состоялся, запускает его сам.
- Повторный вход в текущее назначение: результат раннего запроса игнорируется. Запрос
  только читает данные.

### Ш3. Дата из заголовка ответа

- `buildContext` больше не ждёт дату до плагина. Порядок: сначала записи, потом дата.
- Источник даты по приоритету: заголовок `Date` ответа POST коллекции; затем `Date`
  ответа GET `/` (уже получен, мемоизирован в `TrustedNow`); затем часы машины.
- В `TrustedNow` добавить разбор переданного заголовка с той же диагностикой
  (`source`, `skew`), чтобы `lastSource()` отражал фактический источник.
- Барьер B PRD-31 (`suspendAttempts.js`, `primeTrustedNow`) не меняется: он читает
  мемоизированный ответ `/`.
- При таймауте или ошибке плагина дата для `buildRetakeState` берётся по тому же
  порядку без заголовка POST.

### Ш4. Индикатор ожидания

- `prefetch` заменяет содержимое `#loading` разметкой из эскиза: спиннер
  (`tb-gate-wait`, inline SVG с атрибутами `width`/`height`, чтобы без CSS шаблона он
  оставался кольцом разумного размера) и строка «Проверяем доступ к прохождению…».
  Область `role="status"`, `aria-live="polite"`.
- Через 5 с без вердикта добавляется строка «Проверка может занять до N секунд. Не
  закрывайте окно.», где N = `timeoutMs / 1000`, округлённое вверх. Таймер не пишет в
  DOM, если вердикт уже вынесен.
- Индикатор исчезает сам: любой следующий экран перерисовывает `#app`.
- Стили: `server/scorm/templates/default/styles/theme.css` рядом с `.retake-wall`
  (там же уже живёт встроенный экран блокировки), на токенах `--ou-*`. Шаблоны,
  вынесенные в отдельные репозитории, без этих правил покажут неподвижное кольцо и
  текст; правила им переносятся отдельной задачей.

### Ш5. Спецификации

- `docs/specs/prd-6/retake-cooldown-gate.md`: NFR-06 (бюджет из `timeoutMs`, 30 с по
  умолчанию), ранний старт, индикатор ожидания со ссылкой на эскиз.
- `docs/specs/prd-6/cooldown-trusted-date.md`: NFR-TD-01 и порядок источников даты.
- `CHANGELOG.md` не трогаю: журнал ведёт генератор выпуска.

### Ш6. Тесты

Обновить и дополнить точечными запусками (`npm test -- <path>`):

- `tests/eligibility-gate-date.test.ts`: дата из заголовка POST, откат на `/`, откат
  на часы машины;
- `tests/eligibility-gate-blockwall.test.ts`, `tests/eligibility-gate-lms-name.test.ts`,
  `tests/scorm-retake-acceptance.test.ts`, `tests/retake-gate.test.ts`: новый порядок
  вызовов и отсутствие `reset` в `run`;
- новые случаи: `timeoutMs` из конфига и значение по умолчанию; запрос стартует до
  `window.load`; индикатор и пояснение через 5 с; повторный вход игнорирует результат.

Плюс `npm run check`. Полный прогон набора — только по вашему отдельному разрешению.

### Ш7. Приёмка

- Сверка индикатора с эскизом: сборка пакета `npm run scorm:template`, локальный плеер
  `npm run scorm:player`, скриншоты в светлой и тёмной теме рядом с эскизом.
- Стенд WebTutor: пользователь с длинной историей обучений; в консоли видны момент
  старта запроса, источник даты и время ответа.

## Вне объёма

- Уменьшение `limit` и серверная фильтрация коллекции: время уходит на обработку
  запроса в WebTutor, а не на объём ответа.
- Перенос стилей индикатора в вынесенные шаблоны.
